# unixtime

Unix 时间戳换算小工具：时间戳 ⇄ 可读日期。纯标准库，纯本地，不联网。

## 安装

无需安装，Python 3.10+ 直接运行：

```bash
cd unixtime
python3 -m unixtime 1728000000
```

## 用法

```bash
# 时间戳 -> 可读日期（本地时区 + UTC，带星期）
unixtime 1728000000
# 毫秒时间戳自动识别（13 位数字）
unixtime 1728000000000

# 当前时间戳
unixtime now

# 日期字符串 -> 时间戳（按本地时区解析，可用 --tz 指定）
unixtime "2026-10-05 12:00"
unixtime "2026/10/05"

# 两个时间戳之间的人性化时长
unixtime --diff 1728000000 1728086400
# -> 相差 1 天

# 指定显示时区 / JSON 输出
unixtime 1728000000 --tz Asia/Shanghai
unixtime 1728000000 --json
```

示例输出：

```
（识别为秒时间戳）
时间戳：1728000000（秒）/ 1728000000000（毫秒）
本地时区：2024-10-04 08:00:00 周五
UTC：2024-10-04 00:00:00 周五
```

## 秒 vs 毫秒的识别规则

- 纯数字输入，绝对值 `>= 10^11` 视为**毫秒**，否则视为**秒**。
- 依据：当前秒级时间戳约 `1.7×10^9`（10 位），毫秒级约 `1.7×10^12`（13 位）；
  秒级达到 `10^11` 对应公元 5138 年，现实中不会出现，所以这个分界是安全的。
- 识别结果会打印在 stderr（`（识别为秒时间戳）`），`--json` 模式下不打印。

## 日期字符串支持的格式

`2026-10-05 12:00:00`、`2026-10-05 12:00`、`2026-10-05`、`2026/10/05 12:00:00`、
`2026/10/05`、`2026-10-05T12:00:00`、`20261005120000`，以及带时区偏移的 ISO 8601。

## 诚实说明

- 显示依赖系统 `zoneinfo` 时区数据库；夏令时边界以系统库为准。
- 日期字符串按**源时区**（`--tz` 或本地时区）的当天时间解析，不做"跨午夜"猜测。
- `now` 的毫秒值是调用时刻的快照，前后两次运行自然不同。
